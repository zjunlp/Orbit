# Orbit status

- **Updated at:** 2026-11-10
- **Basis:** P7 (reconciliation, host protection and start limit, capability routing, [catalog](catalog.md)) on P6.5 (coverage, calibration, Harbor GPU sharing, manifest adapter, Python SDK) and P1–P6.
- **Stage:** R0–R2 validated here; R3 LongDS checked with a complete native Codex task, Harbor with oracle/empty samples; R4 only as two daemons on one machine.
- **Blockers:** none for the current release.

## Available

- The npm package [`@zjunlp/orbit`](https://www.npmjs.com/package/@zjunlp/orbit) includes Web, shared skills and generated third-party licenses; one-command native plugins for Claude Code, Codex, dsh and pi. Isolated real installs and skill loading verified. [Plugin guide](../plugin/README.md) · [Release guide](guides/releasing.md).
- `pnpm verify` (Biome, tsc, boundaries, vitest, builds). Auto-started local daemon (127.0.0.1, token/cookie, one-time browser login, private sqlite/state, one writer per home); `orbit run / sweep / ps / show / logs / wait [-g] / cancel / note / resources / doctor / web / auth / notify / bench / node / data`.
- Resource leases with a queue (with reasons); `orbit reconcile` (also every 10 min) removes Docker leftovers of finished runs and releases leaked leases; at most `ORBIT_MAX_STARTING` (4) runs start at once and none under 5 GB free disk; use outside Orbit is respected (busy GPUs, measured CPU use, `MemAvailable`). Docker executor: code snapshot, CDI GPU mapping checked against the lease,
  execution-only timeouts; logs, metrics and outputs collected before cleanup. Opt-in bounded failure checkpoints and `orbit resume` (local Docker, files/session with modification times; unsupported image volumes rejected before execution). [Guide](guides/checkpoints.md). Process backend with a labelling, GPU-limiting docker shim.
- Session linking; Web UI: complete paginated runs with SSE, run detail, trial page, compare, resources, settings, bench; typed-confirmation deletion and digest-confirmed merge dialog; polling pauses in hidden tabs.
- Web/CLI resources and ledger show GPU holders and device capacity/leases. Non-root KVM/DRI/TUN/adb/serial probes; role device paths map to Docker, unavailable classes fail preflight and busy devices queue. GPU model-name filtering; real TUN queue/release and RTX service mapping checked. EGL/Vulkan/CUDA declarations remain unverified. Durable ending phases resume hooks, preserve finalize on cancellation, skip optional render and stop services in reverse dependency order; real Docker recovery/cancellation/timeout/cleanup checked.
- Pre-flight `orbit run|sweep --check` (data, output disk, image, placement); `--smoke '<cmd>'` gates submission.
- Data directory apart from `~/.orbit` (`orbit config data`, `ORBIT_DATA`), doctor disk warnings; owned home symlink targets and existing private files checked/tightened; logical folders (`--folder`, `mv`, `folders`, `export`).
- Agent registry: one declaration per Agent (`codex`, `claude-code`, `pi`, `opencode`, `kimi-cli`, `gemini-cli`, `aider`, `goose`, `qwen-code`, `copilot-cli`, `mini-swe-agent`, `dsh`), user definitions in `agents.json`, `orbit agent ls|show|add|rm|check`, per-Agent install/credentials/argv/transcript. Evaluation configurations name any registered Agent (capabilities keep concrete names; `cli` admits all); `install` Agents are installed inside the Docker run before the command, a failed install is an environment failure. Real runs here: codex, claude-code, and dsh installed in-container on a Harbor-format task; the other nine are `unverified`. ASI/LongDS refuse Agents their native runners do not launch.
- Auth profiles per Agent (kinds depend on the definition); notifications (Feishu, DingTalk, WeCom, Slack, webhook; `feishu-app` bot: `orbit feishu init` QR setup, pairing, read-only `/gpu` `/runs` `/show`, curve cards).
- Native embodied evaluation ([design §9.4a](design.md)) runs independent policies on frozen sample plans with semantic bindings, shared model services, CPU evidence verification and rescore. The [compatibility matrix](guides/embodied-compatibility.md) covers all five LIBERO suites, the four LIBERO-Plus perturbation suites, the six VLABench policy tracks, SimplerEnv fixed grids with a policy-termination option, RoboCasa v0.2 Atomic-24, RoboCasa365 multitask and lifelong evaluation, RoboTwin Clean and Randomized, ManiSkill3 Plate-25 and native tabletop profiles, Meta-World MT50, CALVIN scene D and RLBench MT100/RVT-18. `bench calibrate --policy` runs 2–5-episode checks under a daemon-owned budget. RoboDojo and RoboLab native adapters include frozen catalogs and explicit hold controls; two native controls per family, CPU verification and rescore passed; RoboLab official replay also passed ([task](tasks/20261109-robodojo-robolab.md)). Full-suite statistical equivalence is unverified.
- Bench: solve + verify run per trial, valid-only means (OOM solves invalid); one JSON adapter protocol for built-ins and external executables ([LongDS native multi-turn runner/judge](../examples/bench-adapters/longds/), ResearchClawBench); per-task resources and timeout resolved before adapter planning; `bench usage`
  suggestions; solves with an explicit final model error and no successful model reply are invalid (including native CLI retries); known pre-session Codex config permission failures are invalid/infra; successful partial work is still scored; `bench consolidate` checks preview digests and preserves newly invalid evidence; startup repairs stale trial cleanup; completed invalid retries and task append retain validity; `orbit-bench` skill; `bench rescore` re-verifies from saved solve outputs (history kept). Measured peak memory / CPU / GPU memory on every run. Adapter-declared
  metrics (`score` built in): per-task then over-task means, task-clustered 95% CI, paired Δ in compare. Adapters may declare the benchmark's own aggregation (`official`: errors excluded or counted as failures, per sample or per task), shown next to Orbit's valid-only view; trials carry a closed `failure` kind and `episode`; every finished, rescored or merged job gets an immutable report revision (`orbit bench report`). ASI checks known runner incompatibilities before Agent launch, propagates failures, and shows latest attempt status separately from score validity.
- Harbor format: direct flat-task lookup with nested ID compatibility; separate/shared verifiers share the executable test command and stdout capture; compose services, collect hooks, Harbor's network/image rules; per-role GPU allocation (main/sim/policy, allocated together; explicit service gpusOf can reuse a leased role); service `entrypoint`/GPUs; compose named volumes, binds, restart, `network_mode: none`; opt-in host namespaces and allowlist-as-public recorded as deviations; one Embodied First Exam MetaWorld+ standard task calibrated (oracle 1, empty 0); a vla-eval LIBERO task through the external adapter (empty 0, valid); TB-Science 70/70 and TB 4.0 56/66 supported (oracle/empty checked on samples incl. all 5 compose tasks); jobs record the benchmark commit.
- GUI Web: [task creation, configuration comparison and saved review](guides/gui-bench-web.md); BrowserGym/MiniWoB covers 125 registered tasks with external/empty, and CLI Agents declaring `gui` through a private signed GUI service (`orbit-computer` CLI/MCP; benchmarks declare `requires`). Claude Code completed five sampled BrowserGym tasks through MCP and three CUA-Lite MiniWoB tasks through the shared service; Orbit wires declared stdio MCP servers into Claude/Codex homes. Codex passed a screenshot-only MiniWoB development check through the CLI tool with independently verified signed evidence, enabling `gui`; its auth profile must support container networking. Coordinate/drag overlays, action-id session alignment and an embodied multi-camera/video timeline exist; EFE MetaWorld+ standard now imports executed actions, native reward, render video and session references after scoring, with completeness labels; missing proprioception is not invented. No browser replay or state recovery.
- Multi-node: workers join by token; placement across nodes, size-limited code bundles by hash, named datasets, mirrored logs/metrics, artifact streaming from verified descriptors. Guide: [guides/multi-node.md](guides/multi-node.md).
- GUI hubs: [Cua Bench](../examples/bench-adapters/cua-bench/) basic desktop tasks passed five real empty/oracle pairs and failure/cleanup checks; [CUA-Lite](../examples/bench-adapters/cua-lite/) MiniWoB is calibrated, with isolated WebVoyager/Online-Mind2Web paths and deferred native judges for reviewed subsets. [MobileWorld](../examples/bench-adapters/mobileworld/) and [OSWorld-V2](../examples/bench-adapters/osworld-v2/) adapters retain original task catalogs and single-episode runners; real KVM calibration remains pending. WebVoyager needs its full asset image; Web model calibration remains pending.
- Benchmark discovery uses six independent dimensions with controlled values: domain, task type, evaluation target, interface/modality, environment/interaction and scoring ([vocabulary](design.md#917-benchmark-六维分类-v12026-11-09), [catalog](catalog.md)). Historical C1–C7 labels remain compatibility metadata only ([scope](integration-categories.md)). HumanEval, EFE MetaWorld+, BFCL, τ²-bench, MiniWoB, LIBERO and TextArena have bounded empty/oracle or scripted calibration; BFCL also has a real CLI Agent check. Integration routes remain Harbor (L0), manifest (L1) and Python SDK (L2), with daemon-owned calibration. Web (design §9.16): Overview · Benchmarks · Agents · Configurations · Evaluations · Runs · Resources; the product library contains 30 adapted families, six taxonomy groups and cards/list/domain × task matrix, with same-profile matching and a separate local-registration view. Prior library verification passed ([task](tasks/20261109-benchmark-library.md)); homepage and six dimension-card refinement is verified ([task](tasks/20261109-benchmark-category-cards.md)). Agents expose declared/wired/evidenced capabilities and compatibility; Evaluation configurations group historical settings by name and content revision, with condition-constrained comparisons and recorded configuration sources; an independent Method concept remains undesigned; tool and simulated-user trials use a three-pane conversation view and failure navigation.

## Main gaps
- Product catalog validation is scoped per family, not a promise of local readiness or full-suite parity. Native Policy discovery in Agents is pending despite the existing `/policies` API. Some local adapters lack full taxonomy annotations; historical task snapshots are unchanged and local evidence remains registration-scoped. [Task](tasks/20261109-benchmark-library.md).
- ASI / TB-Science scores not yet compared with official Harbor runs (only oracle-level); codex lacks Harbor's `unified_exec`; no verified GPU graphics-capability checks, allowlist networks, multi-step Harbor tasks or predeclared Harbor MCP tool sets. R4 not run on two real machines; no bundle cache eviction. LongDS's native process runner has no failure checkpoint; real Claude execution/continuation remains unchecked.
- Per-user daemons on one machine (busy 7717 → free port) can lease the same free GPU at once; fix when needed with a shared per-GPU lock. Remaining §9 work: native policy independent-process numerical repeatability and full-suite statistical equivalence, environment pooling/reset (P7), trajectory importers beyond EFE, RoboTwin and LIBERO; EFE standard GPU tasks (shared sim/monitor cards) are translated but not yet run for real; licensed-data volumes (BEHAVIOR, ManiGuard) unsupported.
- Additional bench metrics: tests and fake adapters only; group notifications may fire between solve and verify. Untried: some auth kinds, real IM webhooks (the Feishu app was checked on a phone). No MCP server or dsh/pi session capture/in-container harnesses; no overcommit.
