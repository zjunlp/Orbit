# Orbit status

- **Updated at:** 2026-11-03
- **Basis:** Agent registry (12 built-in Agents, user definitions, `orbit agent`); snapshot index timestamps preserve same-size edit detection; GUI benchmark Web workflow and BrowserGym/MiniWoB phase one retained.
- **Stage:** R0–R2 validated here; R3 LongDS checked with a complete native Codex task, Harbor with oracle/empty samples; R4 only as two daemons on one machine.
- **Blockers:** none for the current release.

## Available

- The npm package [`@zjunlp/orbit`](https://www.npmjs.com/package/@zjunlp/orbit) includes Web, shared skills and generated third-party licenses; one-command native plugins for Claude Code, Codex, dsh and pi. Isolated real installs and skill loading verified. [Plugin guide](../plugin/README.md) · [Release guide](guides/releasing.md).
- `pnpm verify` (Biome, tsc, boundaries, vitest, builds). Auto-started local daemon (127.0.0.1, token/cookie, one-time browser login, private sqlite/state, one writer per home); `orbit run / sweep / ps / show / logs / wait [-g] / cancel / note / resources / doctor / web / auth / notify / bench / node / data`.
- Resource leases with a queue (with reasons); use outside Orbit is respected (busy GPUs, measured CPU use, `MemAvailable`). Docker executor: code snapshot, CDI GPU mapping checked against the lease,
  execution-only timeouts; logs, metrics and outputs collected before cleanup. Opt-in bounded failure checkpoints and `orbit resume` (local Docker, files/session with modification times; unsupported image volumes rejected before execution). [Guide](guides/checkpoints.md). Process backend with a labelling, GPU-limiting docker shim.
- Session linking; Web UI: complete paginated runs with SSE, run detail, trial page, compare, resources, settings, bench; typed-confirmation deletion and digest-confirmed merge dialog; polling pauses in hidden tabs.
- Who holds each GPU (user, command, PID, container/Run, memory, runtime; else unknown) in Web and CLI.
- Pre-flight `orbit run|sweep --check` (data, output disk, image, placement); `--smoke '<cmd>'` gates submission.
- Data directory apart from `~/.orbit` (`orbit config data`, `ORBIT_DATA`), doctor disk warnings; owned home symlink targets and existing private files checked/tightened; logical folders (`--folder`, `mv`, `folders`, `export`).
- Agent registry: one declaration per Agent (`codex`, `claude-code`, `pi`, `opencode`, `kimi-cli`, `gemini-cli`, `aider`, `goose`, `qwen-code`, `copilot-cli`, `mini-swe-agent`, `dsh`), user definitions in `agents.json`, `orbit agent ls|show|add|rm|check`, per-Agent install/credentials/argv/transcript. Bench methods name any registered Agent (capabilities keep concrete names; `cli` admits all); `install` Agents are installed inside the Docker run before the command, a failed install is an environment failure. Real runs here: codex, claude-code, and dsh installed in-container on a Harbor-format task; the other nine are `unverified`. ASI/LongDS refuse Agents their native runners do not launch.
- Auth profiles per Agent (kinds depend on the definition); notifications (Feishu, DingTalk, WeCom, Slack, webhook; `feishu-app` bot: `orbit feishu init` QR setup, pairing, read-only `/gpu` `/runs` `/show`, curve cards).
- Bench: solve + verify run per trial, valid-only means (OOM solves invalid); one JSON adapter protocol
  for built-ins and external executables ([LongDS native multi-turn runner/judge](../examples/bench-adapters/longds/), ResearchClawBench); per-task resources and timeout resolved before adapter planning; `bench usage`
  suggestions; solves whose Agent could not use its model are invalid without a verify run; `bench consolidate` checks preview digests and preserves newly invalid evidence; startup repairs stale trial cleanup; completed invalid retries and task append retain validity; `orbit-bench` skill; `bench rescore` re-verifies from saved solve outputs (history kept). Measured peak memory / CPU / GPU memory on every run. Adapter-declared
  metrics (`score` built in): per-task then over-task means, task-clustered 95% CI, paired Δ in compare. Adapters may declare the benchmark's own aggregation (`official`: errors excluded or counted as failures, per sample or per task), shown next to Orbit's valid-only view; trials carry a closed `failure` kind and `episode`; every finished, rescored or merged job gets an immutable report revision (`orbit bench report`). ASI checks known runner incompatibilities before Agent launch, propagates failures, and shows latest attempt status separately from score validity.
- Harbor format: direct flat-task lookup with nested ID compatibility; separate/shared verifiers share the executable test command and stdout capture; compose services, collect hooks, Harbor's network/image rules; per-role GPU allocation (main/sim/policy, allocated together, never shared); service `entrypoint`/GPUs; compose named volumes, binds, restart, `network_mode: none`; opt-in host namespaces and allowlist-as-public recorded as deviations; one Embodied First Exam MetaWorld+ standard task calibrated (oracle 1, empty 0); a vla-eval LIBERO task through the external adapter (empty 0, valid); TB-Science 70/70 and TB 4.0 56/66 supported (oracle/empty checked on samples incl. all 5 compose tasks); jobs record the benchmark commit.
- GUI Web: [task creation, method comparison and saved review](guides/gui-bench-web.md); BrowserGym/MiniWoB covers 125 registered tasks with external/empty and a private GUI service for CLI Agents. `orbit-computer` CLI/MCP preserves original actions/rewards and service-only evidence; Claude Code passed five real tasks. Coordinate/drag overlays, exact action-id session alignment and an embodied multi-camera/video timeline with joint/action curves are implemented; embodied input is fixture-validated pending adapters. No browser replay or state recovery.
- Multi-node: workers join by token; placement across nodes, size-limited code bundles by hash, named datasets, mirrored logs/metrics, artifact streaming from verified descriptors. Guide: [guides/multi-node.md](guides/multi-node.md).

## Main gaps

- ASI / TB-Science scores not yet compared with official Harbor runs (only oracle-level); codex lacks Harbor's `unified_exec`; no GPU-type placement, allowlist networks, multi-step tasks or MCP servers for Harbor tasks. R4 not run on two real machines; no bundle cache eviction. LongDS's native process runner has no failure checkpoint; real Claude execution/continuation remains unchecked.
- Per-user daemons on one machine (busy 7717 → free port) can lease the same free GPU at once; fix when needed with a shared per-GPU lock.
- Remaining §9 work: first-class policy methods, environment instance pools, a cross-hub trajectory index and a public catalog; real calibration of further GUI and embodied hubs.
- Additional bench metrics: tests and fake adapters only; group notifications may fire between solve and verify. Untried: some auth kinds, real IM webhooks (the Feishu app was checked on a phone). No MCP server or dsh/pi session capture/in-container harnesses; no overcommit.
